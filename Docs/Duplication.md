## Что подтверждено кодом

| Участок | Наблюдение и последствия | Рекомендуемое направление |
| --- | --- | --- |
| `import_libs_internal.py` | Ленивый совместимый фасад сохраняет исторические публичные имена, включая окончательные имена новой ветки | В проекте владельцы импортируются явно; фасад оставлен для внешних клиентов |
| Агрегатор ↔ утилиты | Обратные wildcard-импорты удалены; статический граф верхнего уровня не содержит циклов | Проверять архитектурными и независимыми runtime-тестами |
| `utils_ops.segmentation_ops` ↔ `utils_new.threshold_processing` | Параллельные пороговые функции (`simple_threshold`, `otsu_threshold`, `niblack_threshold`, `sauvola_threshold`, ISODATA и др.). Часть тел совпадает: пороговая вкладка уже импортирует новый модуль напрямую, а агрегатор/старые потребители сохраняют старый | Общий чистый backend с сохранением API и тестами одинаковых входов |
| Первые пять вкладок методов | Панели, сигналы, кадры, показ/состояния маски, список/фокус, ошибки и фоновые задачи вынесены в `ui/segmentation`; численные task bodies — в `utils_new/segmentation/operations`. Контроллеры содержат делегаты и индивидуальные hooks | Общая унификация [завершена](Segmentation_Unification_Status.md); уникальные backend и автоподбор остаются отдельными этапами |
| `tabs.layout_dataset` ↔ `tabs.viewing_dataset` | Совпадают валидатор legacy-аннотаций, detect→OBB, разрешение путей меток, части фоновой проверки и COCO-загрузки | Перенести общее в новый сервис аннотаций/каталога; проверить различия редактора и просмотрщика |
| Старый генератор/валидация/COCO из utils | Неиспользуемый набор удалён после проверки всех потребителей и старых строковых экспортов | Единственные рабочие владельцы находятся в utils_new; [аудит удаления](Utils_Removal_Audit.md) |
| `utils_training/train_unet_worker.py` ↔ `train_unet_worker_рабочий.py` | Копии обучения, датасета, графиков и метрик; GUI запускает первый файл | Второй — кандидат на архивирование после проверки самостоятельных пользователей; наличие копий не означает полную взаимозаменяемость |
| `cluster` | Одинаковые чтение изображений, сбор файлов, запись и преобразования в нескольких самостоятельных скриптах | Общая библиотека I/O и преобразований для CLI |
| `utils_aeb/auto-aeb*` | Несколько самостоятельных вариантов моделей и циклов обучения; есть совпадающие тела | Сначала отделить общую инфраструктуру, сохранив различающиеся архитектуры |
| `tabs.dataset_analysis` → `TrainingImageLabel` | Импорт исправлен на фактического владельца `ui_tabs.dataset_analysis_ui` | Изображения результатов получают специализированный виджет без ошибочного fallback None |
| `utils_ops.deep_learning_ops` | Torch/ONNX импортируются в операциях, доступность проверяется через find_spec | Наличие пакета не доказывает совместимость весов; SegFormer/SAM по-прежнему не реализованы полностью |

`utils.smart_view` больше не используется и удалён: демонстрация ансамблей
переведена на общий DatasetReviewGraphicsView. Рамки всех четырёх полей —
векторный Qt-слой; старый класс отсутствует и в строковом реестре.

## Где модуль используется по назначению

- `utils_new.annotations`: геометрические типы, трансформации и маски отделены от Qt, глобальных настроек и загрузки нейросетей. Генератор использует единый план преобразования изображения и аннотаций.
- `dataset_io_new`, `dataset_validation_new`: повторный экспорт **намеренный**, это фасады совместимости, не ещё одна копия алгоритмов. Для нового кода предпочтительны `dataset_files_new`, `dataset_yolo_labels_new`, `dataset_output_new`, `dataset_pair_validator_new`, `dataset_pair_tools_new`.
- `utils_aeb.yolo_aeb_utils`: в конце файла совместимо реэкспортирует функции геометрии из `utils_new.annotation_processing`. Фактический вызов этих имён идёт в новый модуль, даже если выше сохранилось одноимённое старое определение; его изменение может не влиять на результат.
- `dataset_preparation_bridge`: чистая адаптация данных между существующим UI и новым генератором; фон маски 0 не превращается в обучаемый класс.
- `annotation_processing` и `ui.morphology_ui` обращаются к общему `utils_new.morphology`. Пять вкладок используют четыре операции в пикселях; процентные адаптеры удалены. Пороговый автоподбор переведён на новую схему; градиентный остаётся отключённым.
- `utils_ops`: выбор алгоритма и вычисления вынесены из вкладок. `ui_tabs.setup_*` задаёт индивидуальные параметры, общие панели и сигналы пяти методов собирают `ui.segmentation.panels/controller`. Операции больше не получают Qt через общий агрегатор; GUI-зависимости в старых утилитах указываются явно.
- `utils_training`: обучение запускается отдельным процессом и тем же Python, что GUI; установка пакета в другую среду не исправит импорт worker-процесса.
- `utils_new.autoreseach_utils.metrics_core/prepare/analysis`: базовые метрики, подготовка данных и ранжирование имеют разные роли. Наличие имени `iou` в другом модуле само по себе не доказывает дублирование: формат боксов и задача могут различаться.

## Как получены выводы

Полный [перечень точных копий](Duplicate_Reference.md) строится сравнением AST функций и методов: игнорируются имя функции, строки и docstring; сохраняются аргументы и тело. Включены совпадения между разными файлами размером от 9 строк. Это доказывает совпадение структуры, но не равенство импортированных зависимостей или бизнес-семантики. Одинаковое имя, наследование и простой делегирующий фасад не считаются копией автоматически. Области с похожими, но различающимися телами выше отмечены после чтения кода; оценка «правильности» относится к разделению ответственности, а не является доказательством отсутствия ошибок.

Явные импорты и циклы исправлены в миграции [архитектуры импортов](Import_Architecture_Plan.md). Общие интерфейс, состояния и задачи пяти вкладок описаны в [результате унификации](Segmentation_Unification_Status.md), переход на пиксели — в [отчёте предыдущего этапа](Pixel_Morphology_Plan.md). Дальнейшая консолидация уникальных алгоритмов/валидации и удаление автономных копий остаются отдельной работой: сходство алгоритмов требует отдельной проверки поведения.
