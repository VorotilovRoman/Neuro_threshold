# План исправления архитектуры импортов

Цель: независимая загрузка модулей, предсказуемые зависимости и одинаковое
поведение вкладок при запуске через main и отдельно. Алгоритмы обработки,
форматы данных, модели и UI не перерабатываются.

## Правила целевой архитектуры

- Повторный обычный import безопасен: один модуль кешируется Python в процессе.
  Процессы обучения имеют собственные кеши; разделить их через import нельзя.
- Каждый файл явно импортирует используемые имена у владельца. Утилиты не
  импортируют агрегаторы и вкладки. UI-компоненты не импортируют main.
- Агрегаторы import_libs_*.py остаются совместимыми ленивыми фасадами для
  внешних потребителей; приложение не использует wildcard-импорты.
- Torch, Ultralytics, ONNX и дополнительные модели загружаются только в
  соответствующих функциях/модулях, а не из общих настроек или геометрии.
- Qt принадлежит слою UI; вычисления и headless worker не получают Qt через
  общий импорт. Matplotlib backend worker выбирается до импорта pyplot.
- Канонический запуск вкладки: python -m tabs.<имя> из корня. Прямой запуск
  python /путь/tabs/<имя>.py также получает корень проекта до локальных импортов.
- В одном окружении должен быть один поставщик cv2. Для Qt-приложения выбран
  opencv-python-headless: свой Qt из OpenCV не нужен, поскольку GUI работает
  через PyQt5, вызовов cv2.imshow нет. Ultralytics требует opencv-python в
  метаданных, хотя использует тот же API cv2; установщик нормализует конфликт и
  сообщает об исключении метаданных. Обычный pip install может вернуть конфликт.
- Установка выполняется текущим Python; ошибки не маскируются, Torch и
  torchvision устанавливаются согласованной парой выбранного CPU/CUDA профиля.

## Ограничения проверки

В доступном окружении Torch CPU; CUDA/MPS, реальные веса и обучение на GPU
не проверяются. Необязательные библиотеки проверяются как отсутствующие,
если их нет в окружении; наличие fallback не равнозначно тесту самой модели.
Не запускать обучающие или конвертирующие скрипты с побочными эффектами при
простом сканировании импортов. Изменения settings и результатов тестов не коммитить.

Этап 2: 107 независимых импортов в отдельных процессах прошли; четыре
архитектурных теста и Ruff F821/F822/F823/F403/F405 прошли для всех исходников.
Статический граф импортов верхнего уровня не содержит циклов. Старый
SmartGraphicsView импортируется первым без ошибки. Убран неиспользуемый
Ultralytics из него; Albumentations загружается только при аугментациях.
Обнаруженная неопределённая переменная img_path при добавлении авторазметки
исправлена на self.image_paths[idx].

Уточнение этапа 4: выбран headless-поставщик cv2, а не desktop. Это
исключает конкуренцию Qt plugins двух wheels: GUI реализован через PyQt5,
HighGUI в проекте не используется. Контролируемое исключение pip check
теперь относится только к Ultralytics, а не Albumentations/albucore.

Этап 3: все 15 вкладок запускаются напрямую из постороннего cwd и как модули;
16 выбранных вкладок одновременно создаются и закрываются. Четыре workers
выдают --help без обучения и без SMP. Явная передача centralWidget и общий
ui.application.exec_window обеспечивают уничтожение дерева Qt до завершения
QApplication, без зависимости от порядка finalization Python. Сбор версий
переведён на metadata и больше не загружает Torch при закрытии.

Этап 4: полный python install.py --torch cpu прошёл в рабочем venv; пара
2.11.0+cpu/0.26.0+cpu сохранена. Нормализация удалила opencv-python и
переустановила opencv-python-headless 4.13.0.92. Проверка нового процесса
загрузила NumPy, OpenCV, Torch, torchvision, Ultralytics, ONNX Runtime,
Albumentations, PyQt5. Единственное сообщение pip check — явно описанное
требование Ultralytics к desktop-дистрибутиву. Пять тестов установщика прошли.

Дополнение финального аудита: runtime_policy запрещает AutoInstall Ultralytics
до его загрузки и при уже импортированном backend. Проверка отсутствующего
backend подтверждает, что subprocess/pip не вызывается. Старые AE/VAE scripts
больше не создают каталоги и не меняют seed при импорте; rename_data требует
явную CLI-папку; yolo2voc --help работает без pascal-voc-writer. Полная suite
содержит 19 успешно пройденных тестов, включая обработку данных.
