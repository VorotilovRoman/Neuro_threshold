# План исправления архитектуры импортов

Цель: независимая загрузка модулей, предсказуемые зависимости и одинаковое
поведение вкладок при запуске через main и отдельно. Алгоритмы обработки,
форматы данных, модели и UI не перерабатываются.

## Правила целевой архитектуры

- Повторный обычный import безопасен: один модуль кешируется Python в процессе.
  Процессы обучения имеют собственные кеши; разделить их через import нельзя.
- Каждый файл явно импортирует используемые имена у владельца. Утилиты не
  импортируют агрегаторы и вкладки. UI-компоненты не импортируют main.
- Агрегаторы import_libs_*.py остаются совместимыми ленивыми фасадами для
  внешних потребителей; приложение не использует wildcard-импорты.
- Torch, Ultralytics, ONNX и дополнительные модели загружаются только в
  соответствующих функциях/модулях, а не из общих настроек или геометрии.
- Qt принадлежит слою UI; вычисления и headless worker не получают Qt через
  общий импорт. Matplotlib backend worker выбирается до импорта pyplot.
- Канонический запуск вкладки: python -m tabs.<имя> из корня. Прямой запуск
  python /путь/tabs/<имя>.py также получает корень проекта до локальных импортов.
- В одном окружении должен быть один поставщик cv2. Для Qt-приложения выбран
  opencv-python. Albumentations/albucore требуют headless в метаданных, хотя
  используют тот же API cv2; установщик явно нормализует этот конфликт и
  сообщает об исключении метаданных. Обычный pip install может вернуть конфликт.
- Установка выполняется текущим Python; ошибки не маскируются, Torch и
  torchvision устанавливаются согласованной парой выбранного CPU/CUDA профиля.

## Ограничения проверки

В доступном окружении Torch CPU; CUDA/MPS, реальные веса и обучение на GPU
не проверяются. Необязательные библиотеки проверяются как отсутствующие,
если их нет в окружении; наличие fallback не равнозначно тесту самой модели.
Не запускать обучающие или конвертирующие скрипты с побочными эффектами при
простом сканировании импортов. Изменения settings и результатов тестов не коммитить.
