# Выбор OpenCV для Threshold‑Researcher

[Документация](README.md) · [Установка](Dependencies.md) · [Архитектура](Architecture.md)

Решение от 11 ноября 2026 года: **оставить `opencv-python-headless==4.13.0.92`**.
В текущем проекте переход на `opencv-python` не даёт нужной возможности и не
устраняет конфликт метаданных всей цепочки зависимостей.

## Основания

Приложение создаёт окна через PyQt5; в Python-исходниках нет вызовов
`cv2.imshow`, `cv2.namedWindow`, `cv2.waitKey` или `cv2.destroyAllWindows`.
OpenCV используется для вычислений, чтения/записи изображений и обработки масок.
У установленного wheel `cv2.getBuildInformation()` показывает `GUI: NONE`.
Это относится к GUI **OpenCV**, а не к способности приложения показывать окна Qt.

README самого OpenCV wheel рекомендует headless, когда интерфейс создаётся
другой библиотекой, например PyQt. Он также требует выбрать **один** из четырёх
поставщиков: они используют общее пространство имён `cv2` и пересекающиеся файлы.
Повторный import не выбирает новую версию; опасность возникает при установке
пересекающихся wheels, а не при использовании кеша модулей Python.

Установленные версии содержат следующие требования `Requires-Dist`:

| Потребитель | Требование |
| --- | --- |
| Ultralytics 8.4.36 | `opencv-python>=4.6.0` |
| Albumentations 2.0.8 | `opencv-python-headless>=4.9.0.80` |
| albucore 0.0.24 | `opencv-python-headless>=4.9.0.80` |

Номер версии cv2 4.13 подходит нижним ограничениям API, но pip различает имена
дистрибутивов: наличие headless формально не удовлетворяет требованию к
`opencv-python`. Проверки API и успешный импорт не доказывают совместимость
каждого backend и каждой модели.

## Сравнение вариантов

| Вариант | Поведение и последствия | Решение |
| --- | --- | --- |
| Один headless | PyQt5 обеспечивает GUI; нет дополнительного GUI OpenCV; одно исключение метаданных Ultralytics | Оставить |
| Один desktop `opencv-python` | Требование Ultralytics выполнено, но требования Albumentations/albucore к headless не выполнены; Linux wheels добавляют GUI-зависимости OpenCV, возможен конфликт Qt plugins | Сейчас не требуется |
| Оба wheel | Общие файлы cv2, зависимость от порядка установки и удаления; корректные метаданные не означают исправное окружение | Не использовать |
| Собственная сборка Ultralytics с изменёнными метаданными | Можно убрать исключение, но нужно сопровождать отдельный пакет и проверять обновления | Отдельная задача при необходимости строгого pip check |
| Отдельный venv для YOLO | Разделяет требования, но требует протокола процессов, передачи данных и отдельного развёртывания | Избыточно для текущей задачи |

Подменять установленный `.dist-info`, добавлять фиктивный пакет или скрывать
все сообщения pip check нельзя: это замаскирует действительные несовместимости.

## Как поддерживается выбранный вариант

1. `requirements.txt` фиксирует headless. После resolver-вызова `install.py`
   удаляет конкурирующие wheels и восстанавливает файлы выбранного поставщика.
2. `--repair-opencv` принудительно переустанавливает закреплённый wheel, даже
   если его метаданные присутствуют: файлы могли быть удалены другим wheel.
   При обычной установке неверная версия единственного поставщика также заменяется.
3. `dependency_health.py` проверяет прямые версии, единственного поставщика и
   результат pip check. Он допускает только конкретное сообщение об отсутствующем
   `opencv-python` у Ultralytics. Другие ошибки остаются ошибками.
4. `runtime_policy.configure_ultralytics()` отключает AutoInstall перед импортом
   YOLO и при уже загруженном Ultralytics. Это не даёт проверкам backend вернуть
   desktop wheel во время инференса. Нужные backend устанавливаются явно.

После ручной установки пакетов, при повреждении cv2 или сообщении диагностики:

```bash
python install.py --repair-opencv
python dependency_health.py --load
```

`python -m pip check` по-прежнему возвращает ненулевой код из-за требования
Ultralytics. Это осознанный компромисс, а не полностью согласованный с
метаданными lockfile. Для проверки политики проекта используйте диагностику.

## Проверка изменений

Повторно проверены независимые импорты вкладок и оба порядка, 30 автономных
запусков direct/module, создание и закрытие всех 16 вкладок, workers `--help`,
обработка изображений, геометрия/маски/YOLO/YAML/COCO, аугментации, Torch CPU,
идентичность cv2 при повторных импортах и запрет AutoInstall.
Добавлены две регрессии установщика: ремонт единственного wheel и исправление
его неверной версии. Полная suite теперь содержит 21 тест.

Не проверялись GPU/MPS, обучение и инференс с реальными весами, все optional
backend и интерактивные действия пользователя. Возможный конфликт desktop Qt
plugins — основание избегать лишней зависимости, не заявление о его
воспроизведении на каждой ОС.

## Когда пересмотреть решение

Если появится реальная потребность в HighGUI (`cv2.imshow`), изменятся требования
Ultralytics/Albumentations или потребуется строго чистый pip check, нужно заново
согласовать **всю** цепочку. Простая замена строки headless на desktop этого не
решает. На сервере и в workers наличие CUDA в Torch не требует desktop OpenCV;
CUDA-модули самого OpenCV — отдельная задача сборки.
