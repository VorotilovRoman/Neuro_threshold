# Какие методы подходят для ручной разметки датасета

15 ноября 2026 года, ветка `work`. [План](Report_Evaluation_Plan.md).
Вкладка «Анализ отчётов» сравнивает результаты порогового и градиентного
автоподбора с отдельно выбранной правильной ручной разметкой.
Результат — проверенные методы и **точные полные пресеты**, ранжированные по
фактическому качеству на одном и том же эталонном наборе.

## Порядок работы

1. На пороговой/градиентной вкладке загрузите изображения эталонного набора.
   Выберите режим BBox/OBB/Segment, задайте диапазоны и запустите автоподбор
   для всех снимков. У обеих вкладок одинаковые кнопки, окно диапазонов,
   прогресс и отмена. Для сравнения одного пресета на всём наборе используйте
   одинаковые диапазоны и условия обработки для всех снимков.
2. В анализе отчётов выберите «1. Эталон: YOLO YAML» или «1. Эталон: папка».
   Поддерживаются YOLO BBox, OBB corners/XYWHR и Segment. Формат можно указать
   явно, что особенно полезно для четырёхточечных Segment.
3. Добавьте **оба вида** отчётов кнопкой «2. Добавить отчёты» или
   «2. Папка отчётов». Папка сканируется рекурсивно; последующие добавления
   дополняют набор. «Очистить отчёты» начинает новый набор.
4. Выберите IoU для определения совпадения объектов — по умолчанию `0.50`.
   По умолчанию классы объединены: классические методы ищут геометрию объектов,
   не распознают семантические категории. Включите «Учитывать классы объектов»,
   если одинаковый class ID должен быть обязательным условием совпадения.
5. Нажмите «3. Оценить методы по эталону». Оценка выполняется в фоне и
   останавливается кнопкой. Изменение эталона, формата, IoU или классов
   сбрасывает прежний вывод; запоздалые результаты не применяются.
6. Изучите сводку, лучшие настройки каждого метода и общую таблицу пресетов.
   Для каждого пресета показаны параметры, геометрия разметки, F1,
   Precision/Recall, TP/FP/FN, покрытие, ошибки и отсутствующие вычисления.
   Выберите нужные строки и нажмите «Добавить выбранные пресеты».
7. «Сохранить оценку» записывает сводку и все подробности в отдельную пустую
   папку. «Сохранить топ-пресеты» сохраняет первые десять допустимых настроек.

Пороговые и градиентные пресеты попадают в хранилища соответствующих вкладок.
Сохраняются параметры метода, инверсия, четыре операции морфологии в пикселях,
их порядок и форма ядра, режим аннотаций и оболочка. Новые отчёты также
передают режим уменьшения до 1024 px; при применении такого пресета вкладка
восстанавливает режим и при необходимости перезагружает изображения.

## Что является эталоном

Папка может содержать `images/...` и `labels/...` с одинаковой структурой,
либо изображения и одноимённые TXT рядом. В YAML учитываются все перечисленные
train/val/test, включая вложенные каталоги и списки отдельных изображений.
Для проверки отдельного split выберите его папку или YAML с нужным составом.
Одинаковый физический путь из нескольких секций YAML учитывается один раз.

Можно выбрать папку **только с TXT**. В этом случае сначала загрузите отчёты:
по их именам и исходным размерам восстанавливается состав эталона. Для каждого
TXT должен находиться единственный соответствующий снимок; идентичность
пикселей в этом режиме проверить нельзя. Лишний TXT не игнорируется молча.

Пустой существующий TXT — правильный отрицательный пример. Отсутствующий или
повреждённый TXT, некорректная геометрия, неоднозначное имя и расхождение
размеров не превращаются в отрицательный пример. Они требуют исправления.
Сопоставление учитывает полный путь либо уникальный суффикс каталогов, включая
перенос между Windows/Linux и другим корнем. Если basename одинаковый,
сохраняйте структуру `train/val/...`; выбор наугад запрещён.

Изображения отчётов, которых нет в эталоне, не участвуют в качестве;
их количество выводится отдельно. Все изображения выбранного эталона
остаются в ожидаемом покрытии, даже если для них нет ни одного отчёта.

## Метрики и рейтинг

IoU считается по настоящей геометрии: осевым прямоугольникам, повёрнутым
прямоугольникам или полигонам. OBB/Segment не подменяются охватывающими BBox.
Для точного пересечения, включая невыпуклые полигоны, используется
`shapely==2.1.2` из основных requirements.

Объекты сопоставляются один к одному. Сначала максимизируется число допустимых
совпадений с `IoU ≥ выбранного порога`, затем суммарный IoU. Результат не зависит
от порядка объектов. При учёте классов запрещены межклассовые совпадения.

- `TP` — совпавшие объекты; `FP` — лишние предсказания; `FN` — пропущенные объекты.
- `Precision = TP / (TP + FP)`; `Recall = TP / (TP + FN)`.
- Основной `F1 = 2 TP / (2 TP + FP + FN)` считается **по суммарным счётчикам
  всего эталона** — micro F1. Пустые снимки с лишними объектами увеличивают FP.
- Macro F1 — среднее F1 по снимкам; средний IoU совпавших объектов и средний F1
  по снимкам/IoU `0.50, 0.55, …, 0.95` помогают оценить локализацию.
  Последний показатель **не является mAP**.
- Отдельно сохраняются число отрицательных снимков и доля правильно пустых.
  Если в эталоне вообще нет объектов, вывод оценивает только ложные срабатывания;
  качество обнаружения положительных объектов из него установить нельзя.

Сортировка: micro F1, затем macro F1, средний F1 по IoU и средний IoU TP.
При равенстве качества возможны несколько равноценных пресетов; сводка это
отмечает. Отдельная таблица лучших методов выбирает лучший **целый пресет**
для каждой пары «пороговый/градиентный вид + метод».

Пример: в эталоне два объекта; найден один правильный и один лишний.
`TP=1, FP=1, FN=1`, поэтому Precision=Recall=F1=`0.5`.
Результат только одного удачного снимка не даёт этому пресету F1=1 по датасету.

## Защита от завышенного качества

Рецепт сравнения включает полный пресет **и условия обработки**. Изменение
размера, инверсии, формы/порядка морфологии, режима разметки или оболочки не
смешивается с другими настройками. Пиксельные ядра на разном рабочем размере
могут давать разные результаты.

Для участия в выборе победителя нужно успешное вычисление на **100% снимков
эталона**. Отсутствующие результаты и ошибочные вычисления отражаются отдельно;
они не являются успешными пустыми предсказаниями. Метрики неполного пресета
описывают только проверенную часть, итоговый score/ранг отсутствует.
Если полного покрытия нет ни у одного пресета, программа сообщает, что
победитель не определён, и предлагает дополнить автоподбор.

Повторная загрузка одного и того же результата не увеличивает TP/число снимков.
Противоречащие результаты одного рецепта для одного снимка блокируют оценку:
нужно убрать старую/чужую версию. Незавершённый или повреждённый JSONL также
не игнорируется молча в основном сценарии.

Новые отчёты содержат абсолютный исходный путь, исходный/рабочий размер,
режим уменьшения, SHA-256 исходного файла, исходные аннотации и ошибки каждого
вычисления. Если содержимое изображения изменено, результат не считается
валидным для этого эталона. SHA-256 проверяет идентичность файла, поэтому даже
пересохранение одинаковых пикселей с другими метаданными требует нового отчёта.

JSONL schema_version=1 предыдущего этапа можно оценить по сохранённой геометрии,
но без новых полей нельзя проверить идентичность изображения или автоматически
восстановить resize. Уточните условия либо повторите автоподбор. Старые
свободные текстовые отчёты и таблицы без исходной геометрии не заменяют новые.

Регрессия по тем же строкам больше не определяет рейтинг. Кластеризация,
агрегация лучших строк, удаление пропусков/лишних объектов, фильтр по F1 и
случайная выборка относятся только к свёрнутому режиму «Исследовать строки».
Они не заменяют сохранённый исходный набор для основной оценки.
Показанные параметры выводятся из полного пресета, а не из редактируемых
колонок CSV или произвольной первой строки группы.

## Сохраняемые результаты

| Файл | Содержание |
| --- | --- |
| `summary.md` | Понятный вывод, лучший пресет, лучшие настройки каждого метода, ограничения |
| `rankings.csv` | Все рецепты, метрики, покрытие и причины исключения |
| `best_methods.csv` | Лучший допустимый пресет каждого метода |
| `image_details.csv` | Результат каждого рецепта на каждом снимке, ошибки/пропуски, TP/FP/FN |
| `evaluation.json` | Условия оценки, источник эталона и все полные пресеты |

Файлы связываются устойчивым `recipe_key`. Каталог готовится до публикации;
ошибка не оставляет частичного результата и не перезаписывает непустую папку.
Сохранённый результат описывает выбранный ручной эталон. Чтобы оценить качество
на новых снимках, используйте отдельный контрольный датасет, не участвовавший
в выборе диапазонов и пресета.
