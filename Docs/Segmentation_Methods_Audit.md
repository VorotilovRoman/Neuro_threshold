# Проверка алгоритмов сегментации и обучения

Проверка ветки `work`, 16 ноября 2026 года. Исходный коммит — `0b3d940`.
Основной приоритет — вкладка интерактивных методов. План: [Segmentation_Methods_Plan.md](Segmentation_Methods_Plan.md).

## Вывод

До проверки считать все методы правильно и полноценно реализованными было нельзя.
Найдены ошибки инициализации, координат, передачи параметров, источника обучающих
меток, интерпретации выходов нейросетей и расчёта метрик. Подтверждённые ошибки
исправлены. При этом три графовых алгоритма — **варианты проекта**, а SAM и
SegFormer пока не реализованы. Названия методов сами по себе не подтверждают
соответствие публикации или качество на конкретном датасете.

Классические пороговые/градиентные методы не обучаются. Автоподбор перебирает
рецепты обработки; выбор по эталону — настройка параметров, а не обучение весов.
GrabCut и варианты с GMM оценивают цветовые модели текущего снимка; эти модели
не превращаются в обученный на датасете классификатор. Обучение с сохранением
модели есть у традиционного ML, U-Net/U-Net++, DeepLab и YOLO.

## 1. Пороговые методы

Единый численный владелец — `utils_new/threshold_processing.py`. Старый модуль
`utils_ops/segmentation_ops.py` переэкспортирует эти же функции: ансамбли, вкладка
и автоподбор больше не содержат разные копии математики.

| Метод | Проверенные параметры и применение | Результат / ограничения |
| --- | --- | --- |
| Simple Threshold | `threshold`; сравнение интенсивности с порогом | Корректная глобальная бинаризация OpenCV |
| Otsu | Порог из межклассовой дисперсии | Корректен; освещение/доли классов могут нарушать предположение о гистограмме |
| Triangle | Автоматический порог OpenCV | Корректен; не универсально лучше Otsu |
| Adaptive Mean | Нечётное `window`, смещение `c` | Реальные параметры OpenCV; нечётность проверяется, нет незаметной замены окна |
| Adaptive Gauss | Нечётное `window`, `c` | Аналогично; окно влияет на локальную оценку фона |
| Niblack | `window`, `k`, формула `mean + k·std` | Классическая конвенция со знаком `k`; для сравнения со skimage надо поменять знак `k` |
| Sauvola | `window`, `k`, положительный `r` | Формула проверена по skimage; `r` относится к диапазону uint8, не 0..1 |
| ISODATA | Начальный `init` | Ограничены итерации; возвращается фактически применённый порог без потери дробной части |
| Background Symmetry | `excess` | Собственная эвристика симметрии фонового пика. Исправлены светлый фон, разделение пиков и произвольный порог вне диапазона. Если асимметричного избытка нет — Otsu. Не точное воспроизведение отдельной публикации |
| Row Adaptive | Размер горизонтального блока `window`, `k` | Собственная блочная, не скользящая 2D-адаптация. Исправлена противоположная полярность маски |

Контракт функций: белый пиксель — интенсивность **выше** порога. Вкладка и поиск
затем одинаково инвертируют базовую маску для тёмных объектов; пользовательская
инверсия применяется как отдельная часть рецепта. Для светлых объектов проверяйте
Invert. Морфология выполняется общим модулем, в рабочих пикселях.

Окна локальных 2D-методов должны быть нечётными. Ошибка ручного ввода теперь
сообщается, а не превращается в обработку с другим параметром. Для Row Adaptive
сохранена исходная блочная семантика: размер блока может быть чётным.

После исправления Row Adaptive, Background Symmetry и ISODATA старые результаты
не следует смешивать с новым запуском без пересчёта. JSON-рецепт сохраняет
параметры, но сам по себе не фиксирует версию алгоритма; для эксперимента также
записывайте коммит проекта и версии зависимостей.

## 2. Градиентные методы

| Метод | Параметры | Результат проверки |
| --- | --- | --- |
| Sobel | Нечётное `ksize` 1..31, `scale` | Производные по двум осям, евклидова величина градиента |
| Scharr | `scale`, фиксированное ядро | Размер Sobel для него не используется и скрыт в UI |
| Laplacian | Нечётное `ksize` 1..31, `scale` | Модуль второй производной |
| Canny | `threshold1`, `threshold2`, `aperture` 3/5/7 | Проверяется `threshold1 ≤ threshold2`; OpenCV больше не меняет смысл перевёрнутых порогов молча |
| Prewitt | Фиксированные ядра | Величина двух компонент |
| Roberts | Фиксированные диагональные ядра | Величина двух компонент |
| Kirsch | Восемь направлений | Исправлен максимум модулей на максимум **знаковых** откликов восьми ядер |

Градиентная карта обрезается в диапазон 0..255, затем применяется порог,
морфология, фильтр площади и опциональная заливка контуров. Это детекторы границ,
а не готовые модели объектов: разорванная граница не обязана давать заполненную
маску. Большие `ksize`/`scale` насыщают карту — не стоит расширять диапазоны
автоподбора только ради большего количества вариантов. Настройки заливки,
инверсии и площади входят в сравниваемый рецепт. Старый Kirsch надо пересчитать.

## 3. Интерактивные методы — основные исправления

| Метод | Ввод, параметры и реальная модель | До проверки → после |
| --- | --- | --- |
| GrabCut | ROI и/или FG/BG; режим, итерации | Инициализация RECT стирала штрихи в Both; Both без ROI не запускал алгоритм. Теперь одна согласованная инициализация с жёсткими метками. MASK не подменяется RECT. Проверяются ROI и наличие образцов обоих классов; входная маска копируется |
| Random Walker | FG/BG; `beta`, решатель, RGB/gray | Использовался только gray, предупреждения скрывались. Добавлен RGB, проверены маркеры/пересечения/постоянный снимок. Недоступный `cg_mg` не выбирается без pyamg; `bf` ограничен малыми изображениями |
| Active Contours | ROI; `alpha`, `beta`, `gamma`, итерации, сходимость, форма, сглаживание | Перепутаны `(x,y)` и `(row,col)`, дублировалась конечная точка, скрыто применялось закрытие. Исправлены координаты, начальная кривая, положительный gamma; удалена скрытая морфология |
| Watershed (marker) | Ручные FG/BG либо automatic; в automatic — процент высоты и расстояние между пиками | Раньше только inverse Otsu, а `min_distance` фактически был площадью маркера. Теперь есть настоящий ручной режим; автоматический режим использует пики distance transform с заданным расстоянием |
| Lazy Snapping | Вариант проекта: SLIC, GMM по штрихам, жёсткие FG/BG, цветовые рёбра | Раньше у немаркированных суперпикселей не было цветовой модели классов; конфликты скрывались. Добавлены GMM-стоимости, проверка конфликта в одном суперпикселе и гарантированно сильные терминальные ограничения |
| SuperCut | Вариант проекта: SLIC-граф, доля ROI как prior; размер, compactness, sigma, lambda, color sigma | BGR подавался как RGB/Lab, возможны отрицательные ёмкости, ошибка разреза возвращала пустую маску. Исправлены цвет, ёмкости, соседство и обработка ошибок. Дублирующий Color sigma отключён, getter не передаёт его |
| OneCut | Вариант проекта: GMM внутри/снаружи ROI, SLIC-граф; spatial/data weights, sigma и параметры SLIC | Sigma отбрасывался при вызове; при недостатке данных возвращался сам ROI. Теперь параметр доходит до SLIC, GMM обучаются, неподходящий ввод даёт ошибку без подставного результата |
| Morphological Chan–Vese | **Добавлен**: ROI, итерации, сглаживание, веса однородности внутри/снаружи | Региональная эволюция без требования сильной границы; используется существующий skimage |

Общие изменения:

- Штрих непрерывен даже при редких событиях мыши; радиус кисти задаётся в
  рабочих пикселях. Последний FG/BG-штрих заменяет противоположную метку.
- ROI использует полуоткрытые координаты и включает последний отмеченный пиксель.
  Клик вне снимка не рисует метку на его краю.
- При очистке ввода отменяется применение устаревшего результата фоновой задачи.
  Кнопка запуска без изображения недоступна.
- Нет неявных close/open внутри графовых методов и snakes. Общие четыре операции
  морфологии остаются видимыми и управляемыми пользователем.
- Ошибка min-cut не считается успешной пустой сегментацией. Пустая корректная
  маска и ошибка — разные состояния.
- У методов есть видимые пояснения: какие данные требуются, что означает
  параметр, когда метод подходит и где находится упрощение реализации.

SLIC задаёт **целевое**, а не гарантированное число суперпикселей. При слишком
крупном размере FG/BG могут оказаться в одном узле; программа предлагает
уменьшить размер, а не нарушает разметку. SuperCut/OneCut/Lazy Snapping нельзя
использовать для научного сравнения под именами исходных публикаций без отдельной
полной реализации и проверки. Текущие варианты пригодны как явно описанные
проектные алгоритмы.

Жёсткие штрихи гарантируются базовой сегментацией соответствующих методов.
Последующие инверсия и морфология намеренно меняют маску; для проверки штрихов
отключите постобработку. GrabCut RECT намеренно не использует штрихи, Both —
использует. При автоматическом Watershed предполагаются тёмные объекты на
светлом фоне. Ручной Watershed строит рельеф по grayscale-градиенту.

## 4. Традиционное машинное обучение

| Модель | Обучение и параметры | Состояние |
| --- | --- | --- |
| K-Means | `K`, выбранные признаки, StandardScaler, pixel/SLIC | Кластеризация без эталонных меток; объектный кластер выбирает пользователь. Проверяется число разных образцов; локоть — эвристика, не доказанный оптимум |
| MeanShift | Признаки, нормализация, pixel/SLIC; bandwidth оценивает sklearn | Реальная кластеризация; дорогая на больших пиксельных наборах. Отдельного UI bandwidth пока нет |
| SVM | `kernel`, `C`, признаки, scaler | Реальное supervised-обучение; C/ядро применяются при Train, не при Segment |
| Random Forest | Число деревьев, признаки | Реальное supervised-обучение |
| Decision Tree | Признаки; остальные параметры sklearn по умолчанию | Реальное supervised-обучение; глубина/минимальный лист пока не вынесены в UI |
| XGBoost | Число деревьев, признаки | Путь обучения проверен по коду; сам необязательный backend в этой проверке не устанавливался и не обучался |

Главная старая ошибка: всем supervised-моделям создавались метки inverse Otsu.
Это обучение воспроизведению порога, а не вашей идеальной разметке. Теперь по
умолчанию используется **ручная YOLO-разметка**, а Otsu выбирается явно и назван
псевдометками. Кластеризация не потребляет эти метки.

TXT ищется рядом со снимком или по `images/... → labels/...`. Отсутствующий,
неоднозначный или повреждённый TXT — ошибка; существующий пустой TXT означает
чистый фон. Все объектные классы объединяются в foreground. Segment задаёт
контур, BBox/OBB заполняется целиком: это приближение для обучения пиксельной
сегментации. OBB декодируется в исходном размере до переноса на рабочую сетку.

Признаки, режим SLIC и scaler фиксируются в метаданных модели. Несовпадение
признаков/нормализации или размера SLIC блокирует Segment и предлагает сбросить
настройки либо переобучить модель. Scaler обучается только на обучающих данных
и сохраняется вместе с моделью. Исправлены RGB для SLIC и случай слишком
маленького снимка, когда ранее число суперпикселей становилось нулём.

Это бинарная вкладка, а не полноценный multiclass-редактор. Автоматического
честного train/validation-разбиения и оценки обобщения здесь нет: применить
обученный классификатор к тем же снимкам недостаточно для оценки качества.

## 5. Глубокое обучение и применение моделей

| Backend | Что реально работает | Изменения / ограничения |
| --- | --- | --- |
| U-Net / U-Net++ (SMP) | Обучение, веса+метаданные, inference | Исправлены DiceLoss `classes` (ожидается список, а не число), реальное применение decoder dropout, валидация масок, бинарные индексы, однократная sigmoid и метрики |
| DeepLabV3 / V3+ (SMP) | Обучение, output stride/ASPP, веса+метаданные, inference | Те же контракты масок/DiceLoss/метрик; сохраняются ignore_index и IDs; padding соответствует output stride |
| YOLO-seg | Ultralytics train/predict, conf/IoU/imgsz/save | Маски восстанавливаются без растягивания letterbox. Detect/OBB + Otsu — только явно включённый гибрид. Метрики масок отделены от боксов, используются средние AP, не массивы классов. Disable augmentation выключает и mosaic |
| Custom ONNX | Один вход RGB float32 NCHW, один выход семантической сегментации; CPU Runtime | Метаданные обязательны; logits/probabilities/labels декодируются явно, динамические H/W поддержаны через input_size. Это не универсальный адаптер detection/SAM/NHWC/нескольких входов |
| SAM, SegFormer | Заглушки | В выборе inference отмечены недоступными. Наличие виджетов обучения не означает рабочего backend |

Соглашение о классах: один канал — sigmoid; два — softmax класса 1 с порогом;
более двух — argmax. Выходные индексы сохраняются, не масштабируются в uint8:
иначе классы >255 могли исчезать. Общая вкладка затем объединяет **все классы
кроме 0** в бинарный объект; отдельные классы в экспорт этой вкладки не проходят.
Порог для >2 классов не применяется и отключается в Torch UI.

Препроцессинг Torch/ONNX: BGR→RGB, /255, опциональная ImageNet-нормализация,
hard resize либо центрированный keep_aspect_pad. Для random_crop из обучения
инференс явно использует hard/pad, а не случайно вырезает часть снимка.
Выходы меньшей сетки восстанавливаются перед декодированием; padding убирается,
карта классов возвращается на снимок nearest. Геометрия stride padding/crop
включена и в ONNX-экспорт, включая некратные размеры вроде 513 у DeepLab.

Загрузка весов с отсутствующими параметрами сети теперь даёт ошибку, а не
оставляет часть сети случайной. Все исходные маски проверяются до обучения,
а не только первые 20. Для бинарного режима любой положительный индекс —
объект; для multiclass нужны индексы `0..C-1` и отдельно заданный ignore_index.
RGB-маски без явного преобразования в индексы отклоняются. DeepLab binary
ignore_index исключается из loss и метрик, а не становится foreground.

Базовый U-Net UI рекомендует ImageNet-нормализацию по умолчанию для
предобученного энкодера. Значение остаётся явным и записывается в метаданные;
нельзя включать его только на inference для уже обученных иначе весов.
SMP закреплён в `requirements/optional-training.txt` на проверенной версии 0.6.0.

### Исправление отчётов обучения

Старые поля `mAP50` и `mAP50-95` U-Net/DeepLab **не были AP**: в них записывались
IoU или доля превышений IoU. Эти поля удалены из новых семантических отчётов,
CSV и графиков. Для YOLO настоящие mask/box AP остаются отдельными метриками.

Общий расчёт возвращает IoU, Dice, Precision, Recall, F1, Accuracy. Для бинарных
голов из 1/2 каналов overlap/P/R относятся к объекту; для >2 — macro по классам,
имеющим GT или предсказание. Полностью отсутствующие классы не добавляют единицы
в среднее. F1 усредняется по классам, а не вычисляется из двух уже усреднённых
P/R. Ignore-пиксели не увеличивают Accuracy. Полностью void-набор не имеет оценки.
Визуальные маски, матрицы ошибок и метрики используют один декодер и порог.

## 6. Как улучшать интерактивную разметку дальше

1. **SAM 2.1 tiny/small как отдельный prompt-backend** — наиболее полезный
   следующий прототип для разнообразных объектов и быстрой разметки по кликам/ROI.
   Нужны настоящий адаптер положительных/отрицательных точек, кэш image embeddings,
   корректное восстановление координат, управление жизненным циклом модели и отмена
   устаревших результатов. Текущую SAM-заглушку нельзя считать этой интеграцией.
2. **SimpleClick** — кандидат именно для последовательного уточнения кликами,
   когда начальная маска требует исправлений. Качество и цена зависят от весов,
   backbone и домена. Следует сравнить с SAM на одинаковых снимках и подсказках.
3. **Для простых однородных объектов сначала проверить уже добавленный
   Morphological Chan–Vese**, GrabCut и RGB Random Walker: они обходятся без
   скачивания тяжёлой нейросети. Для соприкасающихся однотипных объектов полезен
   Watershed с контролируемыми маркерами.
4. После выбора backend полезнее добавить undo/redo штрихов, предпросмотр маски
   поверх оригинала и локальную коррекцию, чем ещё несколько малоразличимых
   пороговых эвристик. Сейчас общий Reset есть, истории штрихов ещё нет.

Нельзя утверждать «существенно лучше» без измерения на вашем датасете. Для
GT-полигонов измеряйте IoU/Dice, ошибки отдельных объектов, число положительных
и отрицательных кликов до IoU 0.90/0.95, время первого/повторного результата,
p95 задержки, расход памяти и долю неудачных случаев. Подбор делайте на одной
части данных, финальное сравнение — на другой; снимки одного источника/серии
не следует разносить между ними как независимые примеры.

Для GTX 1650 4 GB из ранее приведённой конфигурации разумно начинать с маленькой
модели и ограниченной рабочей сетки, измеряя VRAM. Не переносить автоматически
пример SAM с bfloat16/compile на эту карту и Windows. Ни веса SAM/SimpleClick,
ни качество этих моделей на пользовательском датасете в этой проверке не тестировались.

## 7. Проверки и воспроизведение

- Численные тесты GrabCut с ROI/без ROI, сохранения FG/BG, координат snakes на
  неквадратном снимке, реальных GMM/min-cut, Random Walker, Watershed и Chan–Vese.
- Niblack/Sauvola сверены с skimage на внутренней области; явно учтён знак k.
  Проверены полярность/порог, формула Kirsch и единый backend ансамблей.
- Настоящее обучение sklearn по ручному TXT, scaler и сохранение/загрузка;
  несовместимые признаки и повреждённые метки проверены как ошибки.
- GUI: непрерывность кисти, замена противоположных меток, zoom/ROI, оба режима
  Watershed, запуск нового Chan–Vese, пресеты и пять вкладок вместе/автономно.
- Настоящие SMP loss/backward/optimizer, train/eval dropout, загрузка весов
  U-Net/DeepLab и применение на неквадратном снимке; pretrained-веса не скачивались.
- Настоящий ONNX Runtime и динамический export padding/crop; logits/probabilities/
  labels и class ID 299; binary void loss и семантические метрики проверены отдельно.
- Дополнительно вне unit-тестов: по одной эпохе U-Net (1/2 канала) и DeepLab (2
  канала) на малом синтетическом датасете, сохранение отчётов/весов и ONNX checker /
  Runtime. Сопоставлены маски Torch и ONNX обученных CPU-моделей.

```bash
NEURO_RUN_GUI_TESTS=1 QT_QPA_PLATFORM=offscreen python -m unittest discover -s tests -v
```

Дополнительно: **174 независимых импорта исходных модулей без ошибок**.

Полный прогон: **151 тест успешно**, включая opt-in GUI и установленные дополнительные backend.

Тесты настоящего SMP/ONNX требуют дополнительных backend; без них соответствующие

Это проверка реализации, не доказательство качества обучения: CUDA/Windows,
полное обучение YOLO/XGBoost, каждый возможный encoder и реальный пользовательский
