# План миграции пяти вкладок сегментации

[Исходный аудит](Segmentation_Tabs_Audit.md) · [Результаты реализации](Segmentation_Refactor_Status.md) · [Документация](README.md)

План уточнён 11 ноября 2026 года по указанию пользователя.
[Пиксельный этап и удаление утилит](Pixel_Morphology_Plan.md) завершены;
поддержка старых настроек и импортов отменена. Общие функции пяти
вкладок переводятся сейчас. **Пороговый и градиентный автоподбор считаются
уникальными функциями и оставлены на последний этап.** Это заменяет прежний
порядок, в котором исправление автоподбора предлагалось первым.

## 1. Границы текущего прохода

Контроллеры threshold, gradient, interactive, traditional_ml и deep_learning
используют общие файловые, геометрические и масочные службы из `utils_new`,
а общие Qt-компоненты — из `ui`. Специфичные параметры и порядок стадий
сохраняются. Данные каждой вкладки независимы.

Не изменять в этом проходе:

- файлы `utils_auto_research`, специальные методы автоподбора двух вкладок,
  его отчёты и диапазоны. Процентные адаптеры UI удалены по новому заданию;
- математику `utils_ops.gradient_ops`, `interactive_ops`, `traditional_ml_ops`,
  `deep_learning_ops`, обучение, форматы старых моделей;
- профили CUDA/OpenCV, порядок Windows-preload Torch и запрет AutoInstall;
- новые class-aware режимы, SAM/SegFormer и фоновые jobs.

Обнаруженные ранее обращения автоподбора к отсутствующему `display_images`
остаются известным дефектом до последнего этапа. Текущий проход не объявляет
автоподбор исправленным или проверенным в работе.

## 2. Архитектурные правила

1. Общие операции выделять через композицию небольших функций и виджетов.
   Не вводить единый BaseWindow с ветвлением по всем алгоритмам.
2. Направление зависимостей: `tabs/ui → utils_new`. Новое вычислительное ядро
   не импортирует Qt, настройки окна, matplotlib backend, Torch или main.
3. У каждой реализации один владелец. Старые публичные пути оставлять
   только при наличии реального потребителя. Старые алиасы settings/presets/view
   удалены после обновления всех импортов; settings-singleton остаётся один.
4. Сохранять нормализованные tuples на границе существующего интерфейса.
   Размеры рабочего кадра и исходного файла задавать явно.
5. Общие методы окна могут остаться короткими делегатами: имена используются
   Qt-сигналами, пресетами и уникальными функциями вкладки.
6. После проверяемого прохода публиковать коммит в `work`, обновлять этот план
   и статус. Историю не переписывать.

## 4. Последующие изменения уникальных функций

Эти задачи не входят в завершённый общий проход. Выполнять отдельными
вертикальными изменениями с проверкой результатов, а не массовым переносом папок.

1. При необходимости перенести владельцев gradient/interactive/ML/DL backend
   из `utils_ops` в `utils_new/segmentation/backends`, оставив фасады. Сначала
   зафиксировать алгоритмические fixtures: порядок стадий и численные результаты.
2. ML: ленивое хранение train-данных, metadata preprocessing, неизменный порядок
   признаков/scaler и чтение старых моделей. Class-aware результат — отдельный режим.
3. DL: typed результат с исходными class/probability data и отдельной бинарной
   маской; контролируемые jobs с revision/cancel/close. Сначала стабильный
   синхронный API, затем фоновые потоки; реальные веса проверять отдельно.
4. Чистый settings_store и новая схема пресетов уже реализованы пиксельным этапом;
   дальнейшие изменения схемы выполнять явно, без скрытого возврата к процентам.
