# Общий автоподбор пороговых и градиентных методов

[Документация](README.md) · [План](Unified_Autoresearch_Plan.md)

12 ноября 2026 года, ветка work. Обе вкладки используют рабочий общий поиск,
одинаковые кнопки, диалог диапазонов, прогресс и отмену. Старые градиентные
перебор и окно настроек удалены; `utils_auto_research` больше не используется.
Все численные службы находятся в `utils_new/autoreseach_utils`, UI — в
`ui/autoreseach_ui`. Написание этих папок сохранено по заданию пользователя.

## Работа в приложении

1. Загрузите изображения в нужную вкладку. Ограничение рабочего размера учитывается
   при поиске так же, как при обычной обработке.
2. В «Диапазоны автоподбора» включите методы и задайте начало/конец/шаг параметров.
   Для градиента доступны Sobel, Scharr, Laplacian, Canny, Prewitt, Roberts, Kirsch.
   По умолчанию включён Sobel с девятью сочетаниями размера ядра и масштаба.
3. На градиентной вкладке диалога «Бинаризация и объекты» задайте диапазон порога
   карты градиента, минимальной площади в процентах снимка и варианты заливки.
4. На общей странице задайте форму и порядок четырёх операций морфологии,
   диапазоны размеров в **пикселях**, инверсию, BBox/OBB/Segment и оболочку.
   0/1 px не меняют маску. Форма и порядок фиксируются для текущего запуска.
5. Выберите текущий снимок или все загруженные изображения и запустите поиск.
   Подтверждение показывает точное число вычислений. Сочетания Canny с первым
   порогом выше второго не включаются ни в перебор, ни в этот счёт.
6. В анализе отчётов откройте папку с результатами обоих видов. Рассчитайте
   mean F1 по IoU, при необходимости примените фильтры/кластеризацию и анализ.
   «Добавить в пресеты» сохраняет пороговые результаты в пороговые пресеты,
   градиентные — в градиентные; смешанный топ также поддерживается.

Диалог не меняет рабочие параметры вкладки при редактировании диапазонов.
Сам перебор не меняет кадр, маску, настройки, отметки или фокус объектов.
Настройки поиска сохраняются отдельно в auto_settings.json и
`auto_settings_gradient.json`, schema_version=1 с kind=threshold/gradient.
Файл другого вида отклоняется. Прежние процентные настройки не преобразуются.

## Численная цепочка и производительность

Пороговая цепочка: threshold → обязательная инверсия → морфология → выбранная
инверсия → объекты. Градиентная: инверсия яркости исходника → градиент →
бинаризация → морфология → фильтр минимальной площади → необязательная заливка
внешних контуров → выбранная инверсия → объекты. Минимальная площадь относится
к рабочему снимку; это прежнее поведение градиентной вкладки.

Обычная вкладка и поиск используют один финализатор градиентной маски.
Нечётные ядра и aperture Canny проверяются до запуска, без незаметного округления.
Подписи порогов Canny обновляются при применении пресета вместе с ползунками.
Регулятор площади на вкладке поддерживает 0–100% с шестью знаками. Пороговые
диапазоны ограничены возможностями рабочих контролов: окна 3–201, C от −20 до 20,
Row Adaptive window 10–500, коэффициенты k/excess с точностью 0.01.
Непредставимые значения отклоняются, а не округляются при возврате пресета.

Сочетания генерируются лениво. Worker загружает по одному кадру и хранит одну
базовую бинаризацию/карту текущего метода и параметров. Морфология, заливка,
инверсия и порог градиента используют её повторно. Количество масок в памяти
не растёт с числом сочетаний; повторный расчёт базового метода проверен тестом.
Обновления прогресса ограничены по частоте, чтобы не заполнять очередь Qt.

Отмена проверяется между вычислениями и кадрами. Текущий нативный вызов не
прерывается принудительно; закрытие окна выставляет отмену и игнорирует поздний
ответ. Окно остаётся отзывчивым благодаря численному worker без QWidget/QPixmap.

## Отчёты и анализ

Пороговые файлы: `*_full_report.txt`, градиентные: `*_gradient_report.txt`.
Оба используют JSONL schema_version=1 с kind=threshold_search/gradient_search,
source/working размерами, полным пресетом v3, аннотациями, боксами для метрик,
записями ошибок и завершающим footer. Начальные пороговые JSONL продолжают читаться.
Старый неструктурированный текстовый формат не поддерживается.

Готовый файл заменяется атомарно после завершения. Отмена сохраняет отдельный
`.partial.txt`, прежний готовый отчёт остаётся на месте. Анализ папки пропускает
partial-файлы и проверяет полноту отчёта. Ошибочные вычисления учитываются в
журнале, но не получают метрику как пустой успешный результат. Коллизии имён
отчётов у изображений с одинаковым stem отклоняются.

Полный preset_json сохраняется в DataFrame/CSV и используется как идентичность
пресета. Группировка точных пресетов и признаки регрессии учитывают kind метода,
все параметры градиента, порог, заливку, фильтр площади, четыре px-операции,
форму/порядок, инверсию и режим объектов. Кластеризация параметров включает
порог/fill/min-area, кластеризация морфологии — четыре размера ядер.
Разные виды не смешиваются в группах.
Сырые JSON-колонки скрыты в таблице; форма, порядок, тип и размеры видны отдельно.

Добавление в пресеты сначала проверяет все выбранные записи и выбирает хранилище
по kind. Параметры не восстанавливаются из текста описания и не теряются при
переходе между отчётом, топом и пресетом. Это проверено настоящей записью обоих
файлов пресетов через UI анализа.

Истинный TXT ищется по image_path отчёта. Отсутствие файла блокирует оценку;
существующий пустой TXT — корректный отрицательный пример. Неверная разметка
отклоняется. Метрики остаются **mean F1 по осевым боксам** без проверки класса,
в том числе для OBB/Segment: это не polygon IoU, качество маски или COCO mAP.
`pred_f1` — описательная оценка на исследованных данных; `actual_f1` — среднее
по изображениям для точно того же полного пресета.

## Владельцы

| Ответственность | Модуль |
| --- | --- |
| Виды, диапазоны, счёт, генерация и проверка пресетов | `utils_new/autoreseach_utils/search_space.py` |
| Общее выполнение, ограниченный cache и запись отчёта | `utils_new/autoreseach_utils/search.py` |
| Градиентная бинаризация и общий финализатор | `utils_new/autoreseach_utils/gradient_processing.py` |
| Reader, ground truth и восстановление пресета | `utils_new/autoreseach_utils/reports.py` |
| Фильтры, кластеризация, метрики и ранжирование | `utils_new/autoreseach_utils/prepare.py`, `metrics_core.py`, `analysis.py` |
| Общий диалог, кнопки и Qt-контроллер | `ui/autoreseach_ui/settings_dialog.py`, `controls.py` |
| UI анализа и результатов | `ui/autoreseach_ui/model_research_ui.py` |

Вычислительные модули не импортируют Qt/Torch/pyplot. Общепроектные геометрия,
морфология, I/O и backend gradient_ops остаются у своих владельцев.
Удалены старые градиентные файлы, экспорты и fixture заморозки; вместо них тест
проверяет новых владельцев и отсутствие прежних исходников/импортов.

## Проверки

Профильные тесты сравнивают все семь градиентных методов с обычной численной
цепочкой, разные заливки/инверсии/фильтры и точное ядро 13 px; проверяют Canny,
cache, совместную загрузку отчётов, кластеризацию/ранжирование, отмену, ошибки,
сохранность вкладки и маршрутизацию пресетов через UI. Обе вкладки проверены
внутри main и автономными запусками общей suite.

Полная suite: **85 тестов успешно** на Linux / Qt offscreen. Проверены
настоящие маски всех семи градиентных методов, cache, ограничения диапазонов,
подписи Canny и площадь 0.5% при возврате пресета на вкладку. Независимо
импортирован **151 прикладной модуль**, ошибок нет; training workers не загружают Qt.
Чистые исследовательские службы импортируются без Qt/Torch/pyplot.
Ruff, компиляция и локальные ссылки в 25 Markdown-файлах проверены.
Код опубликован в work, коммит `ce1eb37`.
Windows/CUDA и реальные нейросетевые веса в этом Linux-проходе не проверяются;
профили зависимостей, OpenCV и runtime_torch не изменялись.
