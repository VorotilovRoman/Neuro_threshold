# Проверка удаления неиспользуемых утилит

> Дополнение: analysis/prepare/metrics_core перенесены из utils в
> [utils_new/autoreseach_utils](Threshold_Autoresearch_Status.md), все потребители
> и строковые экспорты обновлены. Ниже — аудит предыдущего этапа.

[Пиксельная морфология и план](Pixel_Morphology_Plan.md) · [Документация](README.md)

Проверка выполнена перед удалением, затем повторена тестом отсутствия ссылок.
На пиксельном этапе удалены **13 файлов из utils** и **два алиаса из utils_new**. Рабочие функции
других вкладок не удалялись по одному лишь сходству имён или содержимого.

## Как проверено

1. Собран AST-граф всех исходников: обычные/локальные импорты, `from utils import …`,
   константные имена динамических модулей и строковый `_EXPORTS` агрегатора.
2. Проверены динамические точки import_module/__import__, QProcess/CLI и пути
   к `.py` в коде/конфигах/скриптах. У удаляемых библиотек нет собственных
   самостоятельных точек `__main__`. Код автоподбора учитывался как рабочий потребитель.
3. У старого набора генератора/валидации остались ссылки только внутри самого
   удаляемого набора и 38 ленивых экспортов `import_libs_internal`. Из вкладок,
   workers и CLI он больше не вызывался. Экспорты удалены по разрешению отказаться
   от совместимости прежних импортов; после этого внешних ссылок на набор нет.
4. Все потребители settings/presets/view заранее переведены на канонические
   модули. Проверены в том числе отчёты, ансамбли, YOLO+AE/VAE, редактор,
   просмотрщик, диалог пар и `utils_ops.segmentation_ops`.
5. Только после проверки отсутствия оставшихся импортов/строк/путей выполнено
   удаление. `test_removed_utilities_have_no_code_or_registry_consumers` защищает
   это условие на будущее; тесты актуализированы под используемый новый генератор
   и движок геометрических аугментаций.

| Набор | Файлы | Почему можно удалить |
| --- | --- | --- |

| Старые файловые службы генератора/валидатора | `utils/coco_export.py`, `coco_io.py`, `dataset_validation.py`, `unet_export.py`, `unet_io.py`, `yaml_io.py` | Вкладки используют новые leaf-службы, PairValidator и DatasetLoaderMixin; живых вызовов старого набора нет |
| Старые пути настроек/пресетов | `utils/settings.py`, `utils/presets.py` | Все потребители обновлены на ui.settings_service и ui.segmentation.preset_bindings; одноимённых алиасов больше нет |
| Старые пути новых видов | `utils_new/smart_view_new.py`, `utils_new/dataset_review_view.py` | Все Qt-потребители используют ui.image_view и ui.annotation_review_view |

## Что оставлено в utils

| Файл | Рабочие потребители / причина |
| --- | --- |
| `image_io.py` | Анализ датасета, отчёты, ансамбли, YOLO-поиск и YOLO+AE/VAE: чтение/форматы/загрузка. Полный перевод этих вкладок — отдельная работа |
| `analysis.py`, `prepare.py` | Анализ и подготовка таблиц отчётов |
| `metrics_core.py` | Общие метрики для отчётов/анализа/ансамблей |
| `ensemble_utils.py` | Рабочий YOLO+классический ансамбль; чтение морфологии обновлено под новую схему |
| `dataset_analysis_logic.py`, `dataset_audit_logic.py` | Рабочая вкладка анализа датасета |

Отдельные старые адаптеры, у которых остаётся реальный потребитель, не считаются
неиспользуемыми. Например, set_legacy_yolo пока вызывает специальная вкладка
YOLO+AE/VAE; она не входит в пять методов сегментации. Автоматически удалять
весь utils или все функции с legacy в имени нельзя.

## Приёмка

Полная suite с GUI — 53 теста успешно: пять методов, все 16 пунктов main,
автономные запуски и workers, генерация YOLO/масок/YAML/COCO новым движком,
импорты без ML для базовых служб и защита ошибки Torch DLL. Независимые импорты всех 136 оставшихся прикладных модулей проходят.
Старые импорты удалённых файлов больше не поддерживаются по заданию пользователя.
