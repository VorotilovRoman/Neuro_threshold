# Windows: ошибка загрузки c10.dll / WinError 1114

[Установка](Dependencies.md) · [Архитектура](Architecture.md)

## Что показывает полученная трассировка

Ошибка возникает внутри `torch._load_dll_libraries()`: Windows не смогла
инициализировать `c10.dll` либо её зависимость. Это не доказательство загрузки
второй версии cv2. Но порядок загрузки нативных библиотек действительно может
влиять на инициализацию DLL, а прежняя обработка ошибки в приложении была неверной.

`detect_device()` перехватывал сбой импорта Torch и возвращал `cpu`. Затем
`DatasetAnalysisWindow.__init__` повторял import и ловил только `ImportError`;
`OSError` с WinError 1114 выходил наружу и закрывал запуск приложения.

## Изменения

- `runtime_torch.get_torch_runtime()` сохраняет результат одной попытки
  инициализации, включая её ошибку. Повторное определение устройства не запускает
  нативный загрузчик снова. Состояние действует в пределах процесса.
- На Windows `main.py` и все автономные вкладки вызывают подготовку Torch до
  импорта Qt/NumPy/OpenCV. Это предосторожность для порядка загрузки DLL, а не
  гарантия исправления повреждённого wheel или отсутствующего runtime.
- На Linux ранняя подготовка ничего не загружает; ленивый запуск сохранён.
- Вкладка анализа при ошибке Torch сообщает, что нейросетевые функции недоступны.
  Она не выдаёт сбой импорта за исправную работу моделей на CPU.
- YOLO-операции анализа/аудита проверяют сохранённый результат и возвращают
  диагностическую ошибку вместо повторной попытки после неудачной инициализации.
- Если Torch импортирован, но проверка CUDA не удалась, CPU-модуль остаётся
  доступным; причина ошибки CUDA сохраняется отдельно.

Вспомогательные training-процессы имеют собственный загрузчик и собственную
среду процесса: кеш GUI не заменяет работоспособную установку Torch для workers.
После изменения пакетов или runtime завершите приложение и запустите новый процесс.

## Проверка на проблемном Windows

Обновите ветку work и закройте запущенные процессы приложения. Из корня проекта
в PowerShell выполните именно Python нужного venv:

```powershell
.\.venv\Scripts\python.exe -c "import torch; print(torch.__version__); print(torch.cuda.is_available())"
.\.venv\Scripts\python.exe main.py
```

Если **первая команда** тоже падает с DLL-ошибкой, вкладки в этом запуске ещё
не импортировались. Нужно диагностировать установку wheel и Windows runtime,
разрядность Python, выбранную CPU/CUDA сборку и драйвер. По одному коду 1114
нельзя установить конкретную отсутствующую зависимость или виновную библиотеку.
Не скачивайте отдельный c10.dll: он должен соответствовать всей сборке PyTorch.

Для проверки CPU-профиля, если GPU не требуется:

```powershell
.\.venv\Scripts\python.exe install.py --torch cpu
```

Это явная смена профиля; наличие повреждённых файлов той же версии pip может
не исправить обычной установкой. В таком случае безопаснее проверить чистый
отдельный venv, сохранив прежний:

```powershell
py -3.12 -m venv .venv-torch-check
.\.venv-torch-check\Scripts\python.exe -m pip install -r requirements/torch-cpu.txt
.\.venv-torch-check\Scripts\python.exe -c "import torch; print(torch.__version__)"
```

Если чистый CPU-профиль тоже не импортируется, следует проверять системные
runtime-зависимости Windows, включая Microsoft Visual C++ Redistributable x64
для x64 Python, по официальным инструкциям PyTorch/Microsoft. Установка CUDA
Toolkit сама по себе не является универсальным исправлением c10.dll.

## Что проверено здесь

В Linux-среде ошибка OSError с текстом WinError 1114 воспроизведена подменой
загрузчика в тесте. Проверены кеширование неудачи, отсутствие повторной попытки,
открытие двух вкладок анализа, возврат ошибки YOLO-worker, успешный CPU-путь,
сбой проверки CUDA и Windows-only guard ранней загрузки. Реальный Windows
и его c10.dll в этой среде недоступны; первопричина DLL-сбоя пользователя
и устранение её изменением порядка загрузки пока не подтверждены.

Последующая проверка пользователя: standalone import выдаёт 2.11.0+cu126,
GPU GTX 1650 определяется, YOLO-инференс на device=0 выполняется. Для этой
системы добавлен профиль `python install.py --torch cu126`. Это свидетельство
работающего пользовательского запуска; оно не устанавливает первопричину
предыдущего DLL-сбоя и не доказывает исправность каждого действия GUI.
