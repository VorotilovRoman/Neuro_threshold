# Воркер обучения YOLO: AutoBatch, ошибки и завершение процесса

Проверка 20 ноября 2026 года. Основные файлы:
`utils_training/train_yolo_worker.py`, `tabs/deep_learning_training.py`,
`tests/test_yolo_worker.py`.

## Что произошло в присланном журнале

Исходные параметры — `yolo11m.pt`, `imgsz=1280`, `batch=-1`, GTX 1650 4 GB,
Ultralytics 8.4.43 и Torch 2.11.0+cu126. AMP отключила сама Ultralytics после
проверки этой карты. Обучение остановилось до первой эпохи, при профилировании
AutoBatch. CUDA OOM возник и при последующей очистке CUDA-кеша.

**Воркер передавал `batch=-1` правильно.** Отключать AutoBatch для всех запусков
или незаметно заменять его ручным batch не требуется. AutoBatch выполняется
внутри Ultralytics и обычно допускает неудачные пробные размеры.

Проверен исходный код именно пакета **8.4.43**: `utils/autobatch.py` перехватывает
ошибки профилирования и может вернуть резервный batch (по умолчанию 16), но в
`finally` вызывает `torch.cuda.empty_cache()`. Ошибка этой очистки выходит наружу.
Это соответствует присланному traceback. Строка о fallback 16 — сообщение
библиотеки, а не решение нашего воркера.

Значение GPU_mem в неудачном профилировании — диагностическое показание, а не
гарантированная точная оценка минимальной памяти полноценного обучения. Однако
ошибка CUDA OOM подтверждена. Уменьшение batch не гарантирует, что batch=1 при
тех же модели/разрешении поместится; при повторении нужны меньшие imgsz/модель
или другая доступная память GPU. GPU-прогона на GTX 1650 в проверочной среде нет.

## Исправления

| Участок | Было | Теперь |
| --- | --- | --- |
| Обработчик исключений | Локальный `import traceback` делал имя локальным во всём main; ранняя ошибка превращалась в UnboundLocalError | Один импорт на уровне модуля; сохраняются исходный тип, traceback, стадия и ненулевой код завершения |
| CUDA OOM | Вторичная ошибка скрывала источник | Отдельная подсказка OOM и исходный traceback; без дополнительных вызовов CUDA cleanup и скрытого повторного обучения |
| AutoBatch | Sentinel передавался верно, выбранный batch не сохранялся в sidecar | `-1` и доля памяти `(0,1)` передаются без изменения; после старта фиксируется выбранный batch, AMP, device, imgsz |
| Проверка параметров | Некорректный batch/JSON мог дойти до загрузки модели | Проверки JSON, файлов, batch, размеров, эпох и опциональных параметров до загрузки Ultralytics/CUDA |
| Валидация после train | `model.val()` мог использовать собственные defaults | Явные data/imgsz, выбранный batch и разрешённая AMP-точность; результаты в папке текущего запуска |
| Метаданные | Любая модель называлась YOLO-seg; batch оставался -1; время старта записывалось после обучения | Реальная task, отдельные requested/effective batch/imgsz, настоящие времена начала/конца |
| Метрики checkpoint | Метрики проверенной best.pt приписывались и last.pt | Проверенные метрики записываются для фактически выбранной best.pt, либо last.pt при отсутствии best |
| Остановка | Записывался неиспользуемый `stop_training`; после остановки запускались дополнительные val/export | Используется `trainer.stop`; callback получает trainer до первой эпохи. Код остановки 130, отдельное CANCELLED, дополнительная обработка пропускается |
| Ошибка ONNX | Локальный traceback мог ломать вывод других ошибок | Экспорт остаётся необязательным; его сбой имеет явное предупреждение и не стирает сохранённые результаты обучения |
| ONNX metadata | Задача всегда объявлялась segmentation | Указывается реальная задача; отмечена необходимость декодера Ultralytics, а не semantic Custom ONNX |
| Вывод в GUI | UTF-8 и строки PROGRESS могли быть разорваны между порциями QProcess | Инкрементальный UTF-8-декодер, буфер строк, дочитывание последней строки перед finished |
| Завершение GUI | Пользовательская остановка могла показываться как ошибка/успех; best.pt искался среди разных запусков | Остановка выделена отдельно, анализируется точная RESULT_DIR текущего worker |

AutoBatch не реализован повторно и не monkey-patch'ится. Требования пакетов
не изменялись. `amp` остаётся решением Ultralytics, если не задан явно. Для
`optimizer=auto` библиотека также сама выбирает оптимизатор и может игнорировать
ручной lr0; это поведение Ultralytics, а не потеря параметра воркером.

## Параметры и протокол

Основные поля UI остаются прежними: `model`, `data`, `project`, `name`, `epochs`,
`imgsz`, `batch`, `device`, `optimizer`, `lr0`, `lrf`, `disable_aug`,
`close_mosaic`, `mosaic`.

Для CLI/JSON также поддерживаются `amp`, `workers`, `plots`, `pretrained` (bool)
и `export_onnx` (bool, по умолчанию true). Они позволяют запускать диагностическое
CPU-обучение без экспорта, многопроцессных загрузчиков и скачивания pretrained-весов.
Это не полный интерфейс ко всем аргументам Ultralytics.

- `batch=-1`: штатный AutoBatch с целевой долей памяти библиотеки.
- `0 < batch < 1`: штатный AutoBatch с указанной долей памяти.
- Положительный целый batch: ручное значение.
- На CPU/MPS AutoBatch не выполняет CUDA-профилирование; Ultralytics может
  выбрать резервное значение. Оно отражается в логе и метаданных.
- `device=auto` не подменяется принудительным CPU/CUDA; выбор остаётся библиотеке.
- `PROGRESS:percent:epoch:total` — прогресс обучения.
- `RESULT_DIR:path` — фактическая папка запуска, включая автодобавленный суффикс.
- Код 0 и `SUCCESS` — обучение/валидация завершены; необязательный экспорт может
  иметь отдельное предупреждение.
- Код 1 — ошибка; код 130 / `CANCELLED` — остановка.

На Windows `QProcess.terminate()` может завершить процесс без Python-обработчика
сигнала. GUI учитывает нажатие «Остановить» и не показывает его как сбой. Это не
гарантия сохранения checkpoint при принудительном kill: период сохранения
по-прежнему определяет библиотека.

## Проверки

Полный набор проекта: **165 тестов успешно**, включая GUI/runtime. После последних
уточнений sidecar и состояния кнопок повторно пройдены 14 тестов воркера.

14 новых тестов проверяют передачу AutoBatch/доли памяти, раннюю валидацию,
фактические настройки, метрики отдельных checkpoint, пути с кириллицей и BOM,
ошибки train/val/export, остановку, CLI-код выхода и оригинальный traceback.
GUI-тест использует настоящий QProcess: сообщения и символы UTF-8 приходят
побайтово, последняя строка не имеет перевода строки; проверены success и cancel.
В этих тестах Ultralytics заменён контролируемой моделью; они не измеряют VRAM.

Дополнительно выполнено реальное одноэпоховое обучение на маленьком синтетическом
датасете с сохранением best.pt/last.pt, валидацией и metadata:

- установленная Ultralytics 8.4.36: ручной batch=2;
- изолированная Ultralytics **8.4.43**, как в журнале пользователя: batch=-1.
  На CPU библиотека выбрала fallback 16; воркер сохранил именно выбранное значение.

Оба запуска завершились `SUCCESS`. Проверочный пакет 8.4.43 установлен только в
отдельный временный каталог, основной backend и requirements не обновлялись.
Нулевые AP после одной эпохи на нескольких искусственных изображениях не являются
оценкой качества модели; этот прогон проверяет работоспособность pipeline.

```bash
NEURO_RUN_GUI_TESTS=1 QT_QPA_PLATFORM=offscreen python -m unittest discover -s tests -p test_yolo_worker.py -v
```

Ограничение: CUDA-профилирование AutoBatch, расход VRAM, драйвер Windows и AMP
на GTX 1650 не воспроизводились на GPU. Исправления воркера не обещают, что
YOLO11m/1280 теперь поместится в 4 GB.
