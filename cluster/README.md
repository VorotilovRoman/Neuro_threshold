# Кластеризация объектов на снимках

Скрипты группируют по внешнему сходству объекты, найденные YOLO. Текущие
настройки ориентированы на рентгеновские снимки электронных компонентов
и отдельную обработку `IN_pin` / `OUT_pin`.

Конвейер: **снимки → YOLO → кропы → выравнивание → DINOv2 → кластеры → новые снимки**.
DINOv2 используется готовой, без дообучения. Обучаются преобразование признаков
и кластеризация. Смысл групп («тип контакта», «вариант нормы», «дефект») нужно
подтвердить вручную; номер кластера сам по себе не является оценкой качества.

## Скрипты и результаты

| Скрипт | Применение | Вход → результат |
| --- | --- | --- |
| [save_yolo_object_to_path.py](save_yolo_object_to_path.py) | Рекурсивный поиск объектов выбранного класса с фильтрами уверенности, размера и отступом от рамки. Использует предсказания YOLO, ручную разметку не читает. | Снимки и веса YOLO → отдельные кропы. Положительный `padding` расширяет рамку, отрицательный сужает. |
| [canonicalize_crops.py](canonicalize_crops.py) | Выравнивание относительно эталонного кропа: перебор поворотов и отражения, выбор по корреляции яркости. | Кропы и эталон → выровненные копии, `alignment_log.csv`, `alignment_debug.png`. |
| [canonicalize_crops_method2.py](canonicalize_crops_method2.py) | Альтернатива предыдущему скрипту. Режим `features` использует SIFT/AKAZE/ORB и RANSAC для произвольного угла; `correlation` — дискретный перебор; `auto` пробует их последовательно. | Кропы и эталон → выровненные копии, журнал способа/угла/оценки, коллаж. |
| [extract_embeddings.py](extract_embeddings.py) | Извлечение признаков DINOv2, по умолчанию `dinov2_vits14`. Режим `tta-average` усредняет признаки вариантов поворота/отражения. | Кропы → файлы `*_embeding.txt` рядом с ними. Написание суффикса соответствует коду. |
| [cluster_embeddings.py](cluster_embeddings.py) | PCA/UMAP и HDBSCAN/K-Means. `auto` пробует HDBSCAN и при неподходящем результате переходит к K-Means. Для K-Means возможен подбор количества групп по silhouette score. | Эмбеддинги → `labels.csv`, `summary.csv`, график `embedding_scatter.png`, коллажи кластеров и состояние для повторного применения. |
| [test_new_image.py](test_new_image.py) | Применение конвейера к новым снимкам: YOLO, вырезание, выравнивание, DINOv2 и назначение кластера отдельно для каждого класса YOLO. | Снимок/папка, веса и сохранённые состояния → `results.csv`, `collage_all.png`, поклассовые коллажи; опционально кропы и снимки с рамками. |

Два скрипта выравнивания используются как альтернативы одного этапа.
Эмбеддинги рассчитываются по выбранной папке выровненных кропов.
Метка `-1` обозначает шум/непринятый объект; идентификаторы кластеров локальны
для конкретного сохранённого набора и класса YOLO.

## Пример применения

Команды выполняются из корня проекта в его Python-окружении. Пути приведены
как пример и должны быть заменены своими. Для каждого класса используйте
отдельные папки кропов и результатов кластеризации.

### 1. Собрать кропы одного класса

```powershell
python cluster/save_yolo_object_to_path.py -i "D:\dataset\images\train" -o "D:\cluster_data\class0\crops" -m "D:\models\best.pt" --class-id 0 --conf 0.7 --imgsz 1280 --padding -10
```

Имена кропов содержат имя исходного снимка и номер объекта. При совпадении
выходного имени добавляется числовой суффикс.

### 2. Выбрать эталон и выровнять кропы

Выберите типичный объект в желаемой ориентации. Для согласования с текущим
`test_new_image.py` используйте базовый корреляционный вариант:

```powershell
python cluster/canonicalize_crops.py -i "D:\cluster_data\class0\crops" -o "D:\cluster_data\class0\aligned" -r "D:\cluster_data\class0\reference.png" --angles 0,90,180,270
```

Для эксперимента с произвольными углами вместо этой команды можно использовать:

```powershell
python cluster/canonicalize_crops_method2.py -i "D:\cluster_data\class0\crops" -o "D:\cluster_data\class0\aligned_features" -r "D:\cluster_data\class0\reference.png" --match-method auto --feature-detector sift
```

Проверьте журнал и коллаж: удачный численный результат ещё не гарантирует
правильную ориентацию. Скрипт добавляет внешний эталон в список обработки.
По умолчанию существующие выровненные файлы пропускаются; `--overwrite` заменяет их.

### 3. Извлечь признаки и построить группы

```powershell
python cluster/extract_embeddings.py -i "D:\cluster_data\class0\aligned" --model dinov2_vits14 --rotation-mode none --batch-size 8 --device auto
python cluster/cluster_embeddings.py -i "D:\cluster_data\class0\aligned" -o "D:\cluster_data\class0\clusters" --reduce-method umap --reduce-dim 20 --method auto
```

Просмотрите `labels.csv`, `summary.csv` и коллажи. При необходимости задайте
K-Means явно: `--method kmeans -k 4`, если снимков достаточно для такого числа групп.
Вложенные папки кластеризатор обходит только с `--recursive`.

В папке состояния сохраняются `centroids.npy`, `model.json` и, при наличии
снижения размерности, `reducer.joblib`. Исходные изображения по папкам кластеров
не перекладываются: группировка представлена CSV и коллажами.

### 4. Применить результат

Для новых **готовых эмбеддингов**:

```powershell
python cluster/cluster_embeddings.py --predict -i "D:\cluster_data\new_aligned" -m "D:\cluster_data\class0\clusters" -o "D:\cluster_data\predictions" --make-montages
```

Предварительно обработайте новые кропы теми же настройками выравнивания и
извлечения признаков. Результат — `predictions.csv` и, с указанным флагом, коллажи.

Для новых **полных снимков** сначала настройте `CONFIG` в `test_new_image.py`:

- `target_classes`: нужные ID классов YOLO; для примера выше — `[0]`.
- `class_configs[0]["reference"]`: использованный эталон.
- `class_configs[0]["cluster_model"]`: `D:\cluster_data\class0\clusters`.
- `dinov2_model`, параметры выравнивания, `padding` и `min_size`: согласовать
  с подготовкой кропов. Эти настройки не все доступны через CLI.

```powershell
python cluster/test_new_image.py -i "D:\new_images" -m "D:\models\best.pt" -o "D:\cluster_data\results" --conf 0.7 --imgsz 1280
```

Для нескольких классов повторите подготовку отдельно для каждого и добавьте
соответствующие эталоны/папки состояния в `class_configs`.

## Зависимости и связь с приложением

Используются PyTorch/torchvision, Ultralytics, OpenCV, NumPy, Pillow,
scikit-learn, Matplotlib и joblib. UMAP требует `umap-learn`; при его отсутствии
скрипт использует PCA. HDBSCAN доступен через поддерживающую его версию
scikit-learn либо отдельный пакет `hdbscan`.
DINOv2 загружается через `torch.hub`: при первом запуске нужен доступ к модели
или подготовленный кеш. TTA увеличивает фактический батч на число вариантов;
при нехватке памяти уменьшайте `--batch-size`.

Скрипты запускаются отдельно от GUI. Вкладка «Анализ датасета» использует другой
конвейер — CLIP и группировку целых снимков. Прямого вызова этих скриптов из неё
нет. Чтение изображений, выравнивание и загрузка моделей здесь частично дублируются.

## Обнаруженные проблемы

Ниже описаны ограничения текущего кода; документирование их не исправляет.

1. **Разная предобработка при подготовке и применении.** `test_new_image.py`
   повторяет базовое выравнивание, но не features-режим `method2` и не TTA.
   Эти варианты пока нельзя считать согласованным конвейером применения.
2. **Ошибка метрики после PCA/UMAP.** Преобразованные векторы не нормализуются
   перед скалярным произведением с центроидами. Поле `cosine_sim`/`similarity`
   может выходить за диапазон −1…1; `min_sim` нельзя считать калиброванным порогом.
   В `summary.csv` аналогично используется ненормализованное произведение.
3. **Предсказание через центроиды.** Обученные K-Means/HDBSCAN не сохраняются.
   Новые объекты назначаются ближайшему по направлению центроиду; это может
   отличаться от решения исходного алгоритма. Режим `cluster_embeddings.py --predict`
   не имеет порога отклонения новых объектов.
4. **Неполное состояние конвейера.** В `model.json` не фиксируются название/версия
   DINOv2, её предобработка, параметры TTA, эталон и способ выравнивания. При смене режима
   на `--reduce-method none` в прежней папке может остаться старый `reducer.joblib`,
   который загрузчик затем применит. До исправления используйте новую папку состояния.
5. **Ограничения углов не проверяются.** Базовое выравнивание, корреляционный
   режим и TTA фактически используют повороты, кратные 90°. Например, введённые
   45° превращаются в отсутствие поворота. Произвольный угол поддерживает
   features-ветка `method2`.
6. **Повторяющиеся настройки.** В `canonicalize_crops.py`, `extract_embeddings.py`
   и `cluster_embeddings.py` повторяются ключи путей в `CONFIG`; действует последнее
   значение. Встроенные пути привязаны к конкретному локальному датасету,
   а варианты IN/OUT не переключаются единым профилем.
7. **Память.** Выравниватели накапливают все кропы для отладочного коллажа,
   в том числе при `--no-debug`; лимит коллажа ограничивает только отрисовку.
   `test_new_image.py` удерживает исходные и выровненные кропы всех снимков.
8. **Совпадающие имена.** При рекурсивном выравнивании структура подпапок
   не сохраняется. Одинаковые имена могут приводить к пропуску или перезаписи
   результата; разные расширения с одним именем основы делят путь эмбеддинга.
9. **Недостаточная проверка входов.** Не все случаи маленьких выборок,
   несовпадающих размерностей и неконечных значений признаков обрабатываются
   понятными сообщениями до запуска PCA/UMAP/кластеризации.

При доработке сначала следует согласовать и сохранять весь конвейер признаков,
исправить метрику и назначение новых объектов, затем объединить дублирующие
утилиты и ограничить хранение кропов в памяти.
